CARD CUTTER 1.0 USER GUIDE
==========================

WHAT THIS APP DOES
------------------
Card Cutter finds one trading card or graded slab in each photograph, keeps the
outside margin you choose, optionally straightens perspective, and optionally
rotates the result so detected text reads normally. All processing happens on
your computer. Original files are never changed.

Supported systems:
  * Apple Silicon Mac (M-series), macOS 14 or newer
  * 64-bit x64 Windows 10 or Windows 11
  * Python 3.14 (the virtual environment is separate on every computer)

Supported inputs: JPG, JPEG, PNG, and HEIC. A supported image whose filename
has no extension is recognized from its file signature. JPG/PNG keep their
format; HEIC outputs become high-quality JPG files. The app handles one fully
visible card or slab per image.


INSTALLATION
------------
Internet access is required only while setup downloads hash-verified packages
from PyPI. Normal app use does not require internet access.

macOS:
  1. Install Python 3.14 from https://www.python.org/downloads/ if needed.
  2. Open the Card cutter folder.
  3. Right-click setup_macos.command, choose Open, and approve it once if macOS
     asks. This creates .venv and installs requirements.lock.
  4. Double-click run_macos.command whenever you want to use the app.

Windows:
  1. Install 64-bit Python 3.14 from
     https://www.python.org/downloads/windows/ and include the Python Launcher.
  2. Ensure the current Microsoft Visual C++ x64 Redistributable is installed.
     Official download information:
     https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist
  3. In PowerShell, change to the Card cutter folder and run:
       Set-ExecutionPolicy -Scope Process Bypass
       .\setup_windows.ps1
  4. Start the app with:
       .\run_windows.ps1

Windows EXE through GitHub:
  1. Push this project to a private or public GitHub repository.
  2. Open the repository's Actions page.
  3. Select "Build Windows EXE" and choose "Run workflow."
  4. When it finishes, open that workflow run and download the
     CardCutter-Windows-x64 artifact.
  5. Unzip the complete CardCutter folder and run CardCutter.exe inside it.
     Keep the folder together; this safer first release uses PyInstaller's
     one-folder format rather than extracting a large executable on every run.

The GitHub artifact is not digitally code-signed. Windows SmartScreen may show
an unknown-publisher warning even when the build completed successfully. Code
signing requires a separately obtained trusted signing certificate and is not
part of this first release.

On a Windows development computer, .\build_windows.ps1 produces the same
dist\CardCutter\CardCutter.exe. PyInstaller must run on Windows to produce a
Windows executable; the macOS copy cannot cross-compile it.

Setup refuses unsupported CPU/Python combinations, checks that its folder is
writable, installs into .venv only, and never changes the system Python.


WHICH REQUIREMENTS FILE IS WHICH?
---------------------------------
  * requirements.txt is the familiar, human-readable complete runtime list. It
    is convenient to inspect and can be installed with pip, but has no hashes.
  * requirements.in contains only the seven runtime packages Card Cutter chose
    directly. pip-tools uses it as the small source file for dependency updates.
  * requirements.lock contains the full resolved runtime dependency tree with
    exact versions and accepted SHA-256 download hashes. Normal setup uses this.
  * requirements-dev.in adds test, lint, type-check, lock-generation, and audit
    tools to the runtime input. They are not needed to run Card Cutter.
  * requirements-dev.lock is the fully resolved, hash-verified developer setup.

Runtime means software imported or otherwise needed while the app is running.
Developer-only means maintenance tools used to test or inspect the project. A
developer environment includes the runtime packages too, because tests must run
the real app. Use the platform setup script without --dev/-Dev for normal use.


USING SELECTED IMAGES
---------------------
  1. Open the Selected Images tab and click Add images.
  2. Select one or several JPG, JPEG, PNG, or HEIC files.
  3. Choose an output folder.
  4. Set Outside margin. The slider covers 0-250 pixels; the number field
     accepts 0-2000 pixels and has visible -/+ step buttons. Zero ends at the
     detected outside edge. Larger values keep that many source-image pixels
     outside the edge where possible.
  5. Leave Straighten perspective enabled to correct a tilted photograph, or
     disable it for an ordinary image-aligned rectangle crop.
  6. Leave Auto-rotate using text enabled to test 0, 90, 180, and 270 degrees,
     or disable it to retain the photographed orientation.
  7. Click Process selected images. The Before and After panels show progress.

The sun/moon button at the top right switches between light and dark mode. The
choice is saved for the next launch and does not affect exported images.

Pokemon card backs intentionally contain opposing wordmarks, so OCR can see
readable text in both 180-degree orientations. Card Cutter handles this special
case locally: OCR must first identify "Pokemon," the characteristic blue/yellow
back palette must be present, and then the central Pokeball is oriented with its
red half on top. If those signals are weak, the normal OCR confidence safeguard
remains in control instead of forcing a Pokemon-specific guess.


USING A BATCH FOLDER
--------------------
  1. Open Batch Folder and choose the input folder.
  2. Choose a new output folder outside the input folder.
  3. Choose the margin and toggles, then click Process folder recursively.

Images are processed in natural relative-path order, including subfolders. The
same relative folder structure is recreated in the output. Existing files are
never overwritten; a deterministic _cropped_2, _cropped_3, etc. suffix is used.

Cancel stops before the next image. It does not interrupt an image that is
currently being safely written.


OUTPUTS AND REVIEW ITEMS
------------------------
Every run creates processing_report.csv. It records the input, output, status,
crop confidence, clockwise rotation, rotation confidence, and message in the
same order as the run.

Card Cutter does not guess below its confidence thresholds. If it cannot find a
safe crop, or text orientation scores are too close, the unmodified original is
copied into needs_review and the reason is recorded in the report. Turn off the
uncertain optional feature and run that item again if its current orientation or
perspective is already acceptable.

Exports keep the usable color profile where possible, bake in EXIF orientation,
and intentionally omit EXIF/GPS metadata for privacy. Source files remain
byte-for-byte unchanged.


TROUBLESHOOTING
---------------
  * "Needs review": use a more contrasting background, include the whole outer
    edge, reduce glare, or disable Auto-rotate/Straighten for that image.
  * Setup cannot find Python: install exactly Python 3.14 for the supported CPU.
  * Windows Visual C++ error: install Microsoft's current supported x64 runtime
    from the official link above, then rerun setup.
  * HEIC will not open: rerun setup so pillow-heif is restored from the lock.
  * Do not copy .venv between Mac and Windows. Run the platform setup script.
  * To reset settings, use your OS application-settings tools for the
    "Local Card Tools / Card Cutter" application. This does not touch images.


PACKAGE SAFETY AND PRIVACY
--------------------------
The versions below are mirrored in requirements.txt and pinned with hashes in
requirements.lock and requirements-dev.lock. On 2026-10-18,
pip-audit 2.10.1 reported no known vulnerabilities in either complete lock.
This means no matched published advisory was found on that date; it is not a
guarantee that any software is risk-free.

No package can honestly be described as 100% safe. Hash locks verify that the
downloaded files match the reviewed package releases, and pip-audit checks known
published advisories; neither can prove the absence of undiscovered bugs,
malicious upstream changes in a future version, or flaws in native decoders.
The Windows build-only lock was separately audited on 2026-10-18 and pip-audit
reported no known vulnerabilities.

Why Requests and certifi are present even though Card Cutter is offline:
RapidOCR declares Requests as a required dependency and imports its downloader
when resolving OCR models. During engine startup that downloader first checks
whether the packaged model exists and matches its expected SHA-256 value. In
this application it finds the local model and returns before making an HTTP
request. Requests still has to be importable, and Requests declares certifi,
urllib3, idna, and charset-normalizer as dependencies. Certifi is a static set
of trusted certificate-authority certificates used to verify HTTPS identities;
it contains no downloader and opens no connection itself. Removing these files
manually would create an unsupported partial RapidOCR installation even though
the normal Card Cutter path does not use the network code.

Safety codes used below:
  PURE  = Python/data only; no native machine-code extension.
  NATIVE = compiled code; image limits, file validation, and tests reduce risk,
           but malformed-file bugs are possible in any native decoder/runtime.
  MODEL = bundled local model data is loaded for inference.
  NET-I = network is expected only during package installation/auditing.
  NET-0 = the app does not call this package's network functions at runtime.
